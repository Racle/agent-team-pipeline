Add four to the Go API (`api/`) that must be **safe under concurrent use** (the tests run with `go test -race`, hammering one handler from many goroutines; any data race, lost update or deadlock fails).

1. Every note JSON object gets an integer field `likes` (`0` on creation), included in list, get, create and update responses. `PUT` must keep the current `likes` value.
2. `POST /api/notes/{id}/like` atomically adds 1 to `likes` and answers `200` with the updated note JSON; unknown id → `404` with a JSON `{"error": "<non-empty message>"}`; non-integer id → `400`. N concurrent likes on one note must yield exactly N.
3. `POST /api/notes/merge` with JSON body `{"from": <id>, "into": <id>}` atomically moves one note into another: `into`'s `body` becomes `into.body + "\n" + from.body`, `into.likes` becomes the sum of both, `from` is deleted, and the updated `into` note is returned with `200`. If `from == into` → `400`; if either note does not exist (at the moment the merge executes) → `404`, and nothing is changed; invalid JSON → `400`. Concurrent merges in opposite directions (`1→2` and `2→1`) must not deadlock: exactly one succeeds (`200`), the other gets `404`, and the survivor holds the combined likes. Note: `POST /api/notes/merge` must not be confused with `/api/notes/{id}/like` or other id routes.
4. `GET /api/stats` returns `200` `{"requests": <int>, "notes": <int>}`: `requests` is the number of requests handled so far under `/api/notes` (any method, any status, including 400/404 responses; `/api/stats` requests themselves are not counted), `notes` is the current number of notes. The counter must be exact under concurrency.

Existing behaviour and routes are unchanged. Add tests for the new behaviour (preferably also run with `-race`) and keep the existing ones passing.
